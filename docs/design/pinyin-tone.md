# 声调匹配

`zhihao` 敲不出 指导 / 只有 知道、`shishi` 全是同音——同音词多时想用声调缩小范围，
但又不想每次都敲。这份设计定的是：**调号跟着音节内联敲，敲了就按调硬筛，筛空自动降级**；
数据是一张随包旁表 `tone.qj`。`[general] tone_matching` 缺省关，见「配置与装载」。

## 术语

| 词 | 意思 |
|---|---|
| 调号键 | 表示声调的那几个非字母键：`-` 一声、`/` 二声、`=` 三声、`\` 四声、`.` 轻声。 |
| 内联 | 调号敲在音节字母后面（`zhi=`、`ni-hao.`），不设触发段、不进单独的「声调态」。 |
| 旁表 | `tone.qj`：「词 + 词库拼音 → 逐音节调」的随包数据，`pack tone` 生成。 |
| 降级 | 一张调号筛完一个候选都不剩时，扔掉这轮筛选、回无声调的候选。 |

## 键位

| 调 | 键 |
|---|---|
| 一声 | `-` |
| 二声 | `/` |
| 三声 | `=` |
| 四声 | `\` |
| 轻声 | `.` |

`'` 仍是音节分隔符，与调号互不占位（`ni'hao` 与 `ni-hao` 等价，`'` 可以省）。

**与翻页键的冲突**：`[shortcut] page_key` 可选 `[]`（缺省）、`,.`、`-=`。
翻页键在壳层先拦截，选了 `-=` 或 `,.` 的用户那两个调号键就收不到，调号功能残缺——
配置模板的注释里写明了，改页键的人自己权衡；缺省 `[]` 无冲突。

## 输入语义（Core）

- **纯拼音键**：调号只能挂在**有字母可挂**的音节后。开头就是调号、`'` 后直接调号都是坏输入（`segmentable_with_marks` 判 false）。
- **一个音节一个调号**：连着敲第二个调号是**改调**，后一个顶掉前一个（`ni-=` → `ni=`），所以调号只占一个字符、切换调不用先退格。
  在 `Engine::push` 里做（`replaces_tone`）：留在切分器里改的话 `ni-=` 会先被判成坏输入、整段退成英文直输段。
  只在调号当拼音键时替换——开关关着、注音（调号是布局键）、已经是 raw 段时都按原样追加。
- **内联、无触发段**：调号是即时生效的普通键，敲完就参与筛选，删掉就退出筛选。没有独立的「声调态」，不加按键、不改状态机。
- **调号可见**：preedit 显示 `ni=` 而不是 `ni`，用户才知道标的是哪一声。显示走 `Segmentation::marked`（带调号），
  查词键与学习键仍用 `joined`（只有字母）——两者的消费方不同，不能混。
- **配 `[general] tone_matching`（缺省 false）** 才生效。关着时调号是外来字符，行为与从前完全一致（`kai-fan` 直输、`a.b` 走 raw……）。

### 开了之后的输入行为差异

开启后以下行为变化，是调号键占位的代价，逐条列明：

| 输入 | 关（旧行为） | 开（新行为） |
|---|---|---|
| `kai-fan` | `-` 是外来字符 → 直接上屏 `kai-fan` | `-` 挂到 `kai` 当一声 → 拼音 `kāi f…` 按调筛 |
| `a.b` | `.` 是外来字符 → raw 直输 | `.` 挂到 `a` 当轻声 → 拼音 `a` 轻声 |
| `xian` | 既可 西安 也可 先 | 不变（没敲调号就没有任何约束） |
| `ni'hao` | `'` 分隔 | 不变 |
| `ni-=` | 两个 `-` 是坏输入 → raw 直输 | 第二个调号改调 → `ni=`（三声） |

- 全拼的 raw 判定换成**带调号的切分判定**（外来字符 = 非字母、非 `'`、非调号；调号必须挂在字母后才认）。
- 双拼不能复用全拼的切分器（`uixk/` 这种会被误判），单独用「调号出现在任何字母前」判坏。
- 注音不受影响：调号本来就是注音的布局键（空格 = 一声等），**不进** raw 判定分支，只照常参与筛选。
- 表达式快捷键（`v` 开头进 `is_expression`）优先级在调号判定之前，不受影响。
- raw 直输链路本身没改：`C盘` 这类含外来字符的输入照旧进 raw、Enter 原样上屏可用；变的只是判定（字母 + 调号现在算拼音，不再算 raw）。

## 过滤语义（Core）

**硬过滤 + 零命中降级**，只作用于词级候选（单字 / 词 / 短语的拼音查询），不动排序：

1. 从输入里数出每个调号的位置与调值（`typed_tones`）。**位置按「输入的小写字母序号」数，不是按切分位置**——全拼直接数输入字母；双拼 / 注音先解码，按解出的读音逐音节累计。按切分位置数会被歧义切分的前缀候选绕过（`zhi-dao=` 的另一个切分把 `=` 挂在了不同音节上），所以早期那版实现废弃了。
2. 每个候选词，用 `词 + 词库拼音`（与运行时 `hit.pinyin` 逐字一致）查旁表：
   - **查不到这个词** → 不约束（放行）。旁表只收紧、不放逐：词典里有、旁表没收的词照样出。
   - **查到了** → 把调号的字母位换算成该词读音的第几个音节，比旁表第几位码；码是 `a/b/c/d`（1–4 声）、`e`（轻声）、`o`（未知，放行）。
   - **调号落在词没覆盖的字母上**（前缀候选、简拼、输入比词短）→ 这一条不问，放行。
   - 同一个词多种读音（`得` 的 `de2` / `de5`）**任一读音对上就算**（旁表一 key 多码）。
3. **零命中降级**：筛完一个不剩，就当这轮没敲调号，回无声调的候选（`tracing::debug!` 记一条）。`zhi=` 确实没有一声的「知」以外的好词时不要变成打不出字。
4. v1 **不进整句**：`SpanCache` 的键与 Viterbi 词图不动，调号只影响列出来的候选。整句读音按无声调走（与现在一致）。

## 旁表 `tone.qj`

### 格式与键

复用辅码那套 `AuxCodeTable` `.qj` 容器（`Kind::AuxCodeTable`），单表：

- **键**：`"{词库词}\t{词库拼音}"`，如 `知道\tzhi dao`——拼音部分是运行时 `hit.pinyin` 的原样（空格分隔、无调号）。必须与查询侧 `format!("{}\t{}", hit.text, hit.pinyin)` 逐字对齐，差一个空格就查不到 → 该词静默不筛。**键不是裸词**（裸词会与辅码表语义串台）。
- **码**：读音逐音节一个字母，`a`=1 声、`b`=2、`c`=3、`d`=4、`e`=5 轻声、`o`=未知；最多 `MAX_SYLLABLES` = 8 个音节，更长的词跳过。
- 元数据：名称「声调」、许可 `CC-BY-SA-4.0`、署名 CC-CEDICT + Unihan、版本取数据源日期。

### 数据从哪来

`cargo run --release -p qingjian-dict-convert -- pack tone`（缺省输出 `data/generated/tone.qj`）：

1. **CC-CEDICT**（`data/cedict/cedict_ts.u8`，CC BY-SA 4.0）——主源，取词级读音；简体对不上就跳过。
2. **Unihan**（`data/unihan/Unihan_Readings.txt`，Unicode License）——逐字兜底：`kMandarin` / `kHanyuPinlu` / `kXHC1983` 三个字段依次取。
3. 两边都没有的词整词跳过（当前 92,825 词里 1,227 个，1.3%，多为语料挖出的网络词）。

调号是**组合还原**出来的（`strip_tone` 剥数字调 / 预组合字符，再按位置重新挂 U+0300/0301/0304/030C），带调字符本身不进数据。2026-10-05 实测：91,598/92,825 词有码（98.7%），条目 92,202、3.8 MB。

### 为什么按词库拼音而不是 CEDICT 自己的拼音

查询时 `hit.pinyin` 是词库自己的读音（LLM 标注 + Unihan 校验过的那套）。旁表若按 CEDICT 的读音分音节，
多音字词的音节数或拼写一旦与词库不同就对不上位。所以 **pack 时用词库的拼音当键的一部分、逐音节查读音**，
运行时原样对齐，不靠模糊匹配。

## 配置与装载

- 配置：`[general] tone_matching = false`（缺省），模板注释里写了调号键与页键冲突。
- 旁表装载走 `qingjian_platform::code_tables::load_tone_table(path)`：文件不存在或读不出来返回 `None` 并告警，
  引擎 `set_tone_table(None)` 后「不筛」，输入不受影响。开关与表分开：表随包静态装一次，开关随配置热更（macOS `host/config`、Windows `dispatch/reload` 各自 `apply_config`）。
- 各壳的路径：macOS `Resources/tone.qj`（`paths::resource`）、Windows `data/generated/tone.qj`（`generated(&root, …)`）、Linux `data/generated/tone.qj`（`paths::generated`）、CLI `args::default_data_file("tone.qj")`（开了但没表会 warn 一条）。
- 打包：`tools/release/data-bundle.sh` 的 `PRODUCT_FILES` 含 `tone.qj`（缺文件直接报错，提示先生成）；
  `apps/macos/scripts/bundle.sh` 把它拷进 `Contents/Resources/`（有就拷）。生成命令补在 `assets/lexicon/QINGJIAN.md` 第 7 步。

## 否决过的方案

| 方案 | 为什么不做 |
|---|---|
| 触发段（先按某个键进「声调态」再敲调号） | 多一次按键、多一个状态要画进 preedit；内联已经够表达。 |
| 软加权（调对的排前面、不硬删） | 排序变化不可预期，用户看不出「筛」在哪；硬筛 + 降级行为可解释。 |
| 进整句（词图边按调约束） | `SpanCache` 的键要带调，牵动纠错、模糊音、学习回放，v1 范围失控。 |
| 按切分下标过滤 | 歧义切分的前缀候选可绕过（见「过滤语义」第 1 条），已废弃。 |

## 后续不做 / 待办

- 开关已在 macOS 与 Windows 设置面板的「通用」页（勾选框，注音与关方案下置灰，见 `Scheme::supports_tone_matching`）；Linux 没有设置界面，仍只读配置文件。
- 简拼（`zhid` 这种缩写）位置换算已按字母位处理，但简拼候选的读音是补全出来的，行为以「放行」为主，等有用户反馈再说。
- 调号在候选里显示注记（给对调的词标个调号图标）没有做。
