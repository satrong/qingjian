# 手机推送上屏（remote input）

给「电脑没有麦克风」这件事的一个解法：输入法进程自己开一个局域网 Web 服务，手机浏览器打开一页表单，
提交文本，输入法把文本插进电脑端当前的输入框。手机上不装任何 App、不用 HTTPS、不给麦克风权限。

## 为什么是这个形态

最初的设想是「手机当麦克风 → 手机输入法解析 → 文本传到电脑」，中间要写一个手机 App。
最后砍掉 App 与浏览器语音识别，因为：**手机上本来就有输入法，它的语音识别（讯飞、搜狗、iOS 系统听写）比电脑上的方案好，
而且不占电脑资源**。让用户在手机浏览器里点一下输入框、切到手机输入法、按它的麦克风说话，识别结果就落进表单，
点发送即可——语音这一步完全由手机自己完成，我们只负责「文本从手机到电脑」这一段。

于是这一段没有 App、没有蓝牙、没有云中转，也没有 Core 的事：手机给的是**成品文本**，不是拼音，
所以不经过候选、排序与整句，走各平台自己的「插入文本」通道（macOS `insertText:`、TSF `ITfInsertAtSelection`、
fcitx5 `commitString`）。

明确不做：

- **不做手机 App**（Android 也不做）。省掉签名、分发、权限弹窗，iOS 还能直接躲开「键盘扩展不能录音」的限制。
- **不做浏览器语音识别**（`webkitSpeechRecognition`）。它要求安全上下文，局域网 IP 上拿不到麦克风，等于没有。
- **不做 mDNS 自动发现**。`*.local` 发现要手机端也跑原生客户端才能枚举 Web API，正好把「不装 App」这个最大的优点破坏掉。
- **不做 HTTPS / TLS**。要证书、要手机装 CA 根证书，与「扫个码就能用」冲突。明文的安全边界见下。
- **不做双向**。先只做手机 → 电脑；回传（电脑上显示手机状态、手机上远程选词）不在这一版。

## 链路

```
手机浏览器 ──HTTP──▶ qingjian-remote-web（输入法进程内）
                       │  mpsc::Sender<Incoming>，只传字符串，不碰平台 API
                       ▼
                    各平台的壳：insert_text / ITfInsertAtSelection / commitString
```

三个前提，缺一条体验就不成立：

1. **电脑端已经选中清简，且光标在文本框里。** macOS 不允许程序偷偷切输入源，所以推送那一刻清纲要是在用的那个输入源。
2. **手机与电脑在同一局域网**，且不是访客网络（访客网络普遍开 AP 隔离，双向不通）。
3. **首次要放行系统防火墙**：未公证的签名首次监听会弹「是否允许接受传入连接」。

## 协议

| 路由 | 说明 |
|---|---|
| `GET /` | 一页内联 HTML：一个多行输入框、发送、清空、一行状态 |
| `POST /commit` | body 为 `text/plain`，内容就是要上屏的文本 |
| `GET /status` | 服务是否活着（页面用来判断电脑是不是连不上） |

状态码就是协议，页面按它显示中文原因：

| 状态 | 含义 |
|---|---|
| `200` | 已上屏 |
| `400` | 请求或文本不合法（空文本、非 UTF-8） |
| `401` | 令牌不对，或来源不是这一页 |
| `404` / `405` | 路由 / 方法不对 |
| `409` | 电脑端现在没有可输入的窗口，或壳主动拒绝（安全输入、密码框） |
| `413` | 文本超过上限（缺省 4096 字节） |
| `429` | 提交太频繁（60 次/分） |
| `503` | 壳在时限内没答复（可能已休眠），或该功能已关闭 |

限长与清洗在服务这一侧就做完，不留给壳：控制字符（连 ANSI 转义用的 ESC）、DEL、C1 区与双向文本控制符一律去掉，
CRLF 收成一个换行，零宽连接符保留（emoji 序列要用）。清洗后为空算无效。

## 配对与安全边界

**同一局域网内的任何人都能访问这个端口**，所以唯一的凭据是一枚 128 位随机令牌（`Config::generate_token`，壳持久化到配置），
绑定方式是二维码：菜单里给出二维码与 `http://<ip>:23333/?k=<令牌>`，页面读走令牌存进 `localStorage` 后立刻
`history.replaceState` 把地址栏洗掉。

两条硬要求：

- **`POST` 必须带自定义头 `X-Qingjian-Token`，且服务端永不返回 CORS 头。** 自定义头不在 CORS 安全列表里，
  跨源请求会先触发预检、拿不到响应，于是浏览器自己把它挡掉。这一层是明文 HTTP 下唯一能防住「同局域网页面 CSRF」的东西，
  去掉它等于开一个任意文本注入的口子。
- **再核一次 `Origin` 与 `Host` 同源**，挡住不触发预检就能发出的那类请求（表单、简单 fetch）。

令牌不打日志、不进 URL 之外的地方；响应 `Cache-Control: no-store`；配对没有手输短码这条退路（弱化它不值得）。

服务默认不开，由壳在用户显式开启时才 `Server::start`；关掉就 drop，socket 立刻释放。端口固定 23333——
手机侧只要记住「IP + 端口」，撞端口就在菜单里提示，不自动换端口（换了手机上存的地址就失效）。

## 各平台的接入点

- **Linux**：`LinuxEvent` 加一个变体，Server 分派后直接 `commitString`，绕过 Engine。Server 常驻，最省事。
- **Windows**：Server 侧挑「最近活跃且非密码框」的 session，DLL 收到后开一次编辑会话，复用 `composition::apply` 把文本当 `commit` 喂进去。
- **macOS**（唯一需要设计的地方）：进来的时候**可能根本没有 client**——输入源已启用但没人在打字时，
  `insertText:` 没有收件人。所以 `Host` 上挂一个待插入队列，主线程在 `activate_server:`（那里能拿到 client）先 flush 再起 session；
  存着的文本有超时（30 秒）以免很久以后插到不相干的位置。上屏走 IMK 的 `insertText:` 而不是 CGEvent 合成按键，
  因此不需要辅助功能权限。安全输入期间（`IsSecureEventInputEnabled`）直接回 `409`。

## 配置

`[remote]` 分节（缺省关）：`enabled` / `port` / `token`。令牌在第一次启动时生成并写回配置，菜单开关与面板按钮都只写这个文件。
菜单里两项：「手机输入」（开关）与「手机输入设置…」（打开面板：二维码、地址、开关、复制）。菜单底部在开着时显示一行地址。
